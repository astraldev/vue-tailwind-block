The package has one option, `binding`. It renames the `classes`
variable, for example when a prop already uses that name.

::field-group
  :::field{name="binding" type="string" default="'classes'"}
  Name of the variable the template and `<script setup>` read the block
  from. It must be a valid JavaScript identifier.
  :::
::

## Usage

::code-group
```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['vue-tailwind-block/nuxt'],
  tailwindBlock: {
    binding: 'styles',
  },
})
```

```ts [vite.config.ts]
export default defineConfig({
  plugins: [tailwindBlock({ binding: 'styles' }), vue()],
})
```

```json [tsconfig.app.json]
{
  "vueCompilerOptions": {
    "plugins": [{ "name": "vue-tailwind-block/volar", "binding": "styles" }]
  }
}
```
::

Every component then reads `styles` instead:

```vue [Card.vue]
<template>
  <div :class="styles.root" />
</template>
```

::warning
Outside Nuxt, set the same `binding` in `vite.config.ts` and in the
`tsconfig`. If they are different, the editor will accept a name which
will not be present in the build, and the component will fail to render.
The Nuxt module passes its option to both plugins, so a Nuxt project sets
it once.
::

::code-group
```ts [Correct]
// #vite.config.ts
tailwindBlock({ binding: 'styles' })

// #tsconfig.app.json
"plugins": [{ "name": "vue-tailwind-block/volar", "binding": "styles" }]
```

```ts [Wrong]
// #vite.config.ts
tailwindBlock({ binding: 'styles' })

// #tsconfig.app.json
// no binding, so the editor accepts `classes`, which the build never declares
"plugins": [{ "name": "vue-tailwind-block/volar" }]
```
::

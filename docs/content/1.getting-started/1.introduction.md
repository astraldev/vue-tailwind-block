`vue-tailwind-block` lets a Vue component keep its Tailwind classes in a
`<tailwind>` block instead of in the template. The block is YAML, grouped
under names you choose, and the template reads it from a variable called
`classes`.

This alert has a box, a title and a body, and two tones. Each tone changes
the colors of the box and the title, so the block groups the tone classes
under the part they style:

::code-preview
:::div{.flex.w-full.flex-col.gap-3}
::::example-alert{tone="info" title="Update available"}
Version 2.0 is ready to install.
::::

::::example-alert{tone="danger" title="Payment failed"}
Your card was declined. Check the details and try again.
::::
:::

#code
```vue [Alert.vue]
<script setup lang="ts">
defineProps<{ tone: 'info' | 'danger', title: string }>()
</script>

<template>
  <div role="alert" :class="[classes.root, classes.tones[tone].root]">
    <p :class="[classes.title, classes.tones[tone].title]">{{ title }}</p>
    <p :class="classes.body"><slot /></p>
  </div>
</template>

<tailwind lang="yaml">
root: flex flex-col gap-1 rounded-lg border px-4 py-3 text-sm
title: font-medium
body: opacity-80

# each tone colors the box and the title, the body stays neutral
tones:
  info:
    root: border-sky-500/30 bg-sky-500/10
    title: text-sky-500
  danger:
    root: border-red-500/30 bg-red-500/10
    title: text-red-500
</tailwind>
```
::

Written inline, the same alert needs a lookup object for the tones, read
in two places. With the block, the template only says which part gets
which group, and adding a `warning` tone touches the YAML alone.

The block never reaches the browser. The build replaces it with a plain
object at the top of `<script setup>`, and a plugin for the Vue language
tools types that object in the editor and in `vue-tsc`.

## When to use it

A block helps most in components with variants, sizes or states. A
`<div>` with three classes reads better with the classes left in the
template.

The editor and `vue-tsc` never run the build, so they do not know about
`classes` on their own. The editor plugin types it from the block.

## Setup

Nuxt needs no setup. With Vite, add the plugin to the `tsconfig` that
includes your `.vue` files:

```json [tsconfig.app.json]
{
  "vueCompilerOptions": {
    "plugins": [{ "name": "vue-tailwind-block/volar" }]
  }
}
```

## Keys

`classes` has the keys of the block, and each value is a `string`.
Hovering a key shows its classes. For this block:

```yaml [Button.vue]
root: inline-flex items-center rounded-md
variants:
  solid: bg-sky-600 text-white hover:bg-sky-500
  outline: border border-zinc-300 hover:bg-zinc-50
```

::code-group
```ts [Hover on classes]
const classes: {
  root: string
  variants: {
    solid: string
    outline: string
  }
}
```

```ts [Hover on classes.variants.solid]
(property) solid: string
// bg-sky-600 text-white hover:bg-sky-500
```
::

A key that is not in the block is a type error, in the template and in
the script. That includes a prop used as an index:

```vue [Button.vue]
<script setup lang="ts">
const props = defineProps<{ variant: 'solid' | 'outline' | 'ghost' }>()
</script>

<template>
  <!-- error: 'ghost' is not a key of classes.variants -->
  <button :class="classes.variants[props.variant]" />
</template>
```

Index errors need `strict` in the `tsconfig`, which `create-vue` and
Nuxt turn on by default.

## Errors

Problems in the block are underlined on the block:

- **A YAML syntax error**, like a key written twice, underlines the line
  it happens on.
- **An invalid value**, like an empty key, underlines the whole block and
  names the key in the message.
- **A `lang` other than `yaml` or `yml`** underlines the whole block.

While the block is invalid, `classes` is typed `any`, so the mistake is
reported once instead of at every use.

::note
`classes` is typed only in `<script setup lang="ts">` components. In a
JavaScript component it is `any`.
::

## CI

`vue-tsc` loads the same plugin, so the same errors fail CI:

```bash
pnpm vue-tsc --noEmit
```

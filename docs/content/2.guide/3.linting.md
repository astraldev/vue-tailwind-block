Tailwind ESLint rules, such as the ones in
[eslint-plugin-better-tailwindcss](https://github.com/schoero/eslint-plugin-better-tailwindcss){target="_blank"},
check class strings in code. The ESLint integration hands them each
entry of the block, and writes their reports and fixes back to the YAML.

## Setup

Spread `tailwindBlock.configs.recommended` after the config of
`eslint-plugin-vue`, then add your Tailwind rules:

```js [eslint.config.js]
import betterTailwindcss from 'eslint-plugin-better-tailwindcss'
import pluginVue from 'eslint-plugin-vue'
import tailwindBlock from 'vue-tailwind-block/eslint'

export default [
  ...pluginVue.configs['flat/recommended'],
  ...tailwindBlock.configs.recommended,
  {
    ...betterTailwindcss.configs.stylistic,
    settings: {
      'better-tailwindcss': { entryPoint: 'src/style.css' },
    },
  },
]
```

Keep it after `eslint-plugin-vue`. ESLint runs one processor per file,
and the last one set wins. The integration runs the Vue processor inside
its own, so both keep working.

## Fixes

`eslint --fix` applies the rules' fixes inside the block. With the
`stylistic` config, classes are put in Tailwind's order:

::code-group
```yaml [Before]
root:
  - p-4 flex bg-white
  - "@md:flex underline"
```

```yaml [After eslint --fix]
root:
  - flex bg-white p-4
  - "underline"
  - "@md:flex"
```
::

A fix that splits a line, such as line wrapping, turns the entry into
several list entries.

::note
ESLint checks each entry as a JavaScript string. An entry that would
change meaning inside a string, such as one with a backslash like
`content-['\201C']`, is skipped and left as written.
::

## Reported rules

Only rules with `tailwind` in their id report on blocks. Pass rule ids
or patterns to `createConfig` to change that:

```js [eslint.config.js]
import tailwindBlock from 'vue-tailwind-block/eslint'

export default [
  ...tailwindBlock.createConfig({ rules: [/tailwind/, 'my-plugin/class-names'] }),
]
```
